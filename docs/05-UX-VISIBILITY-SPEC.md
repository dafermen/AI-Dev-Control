# UX Visibility Specification
Every phase should produce something a human can understand visually.

## Navigation
Dashboard · Projects · Current Task · Live Development · Reviews · Documentation · Timeline · Usage & Cost · Settings

## Live Development
- **Left:** repository tree/status.
- **Center:** active file and working/staged diff.
- **Right:** task, objective, status, scope, risk, elapsed time, available usage/cost telemetry, Pause, Stop, Request Change.
- **Bottom:** terminal/build/test activity.

## Timeline
Record task/plan/approval events, file activity, commands, tests, scope requests, pause/resume, reviews and acceptance/rejection.

Markdown documentation must render inside the application with navigation/history.

Backend work should still create a visible artifact: status/API view, diagram, event timeline, test report, documentation view or UI integration. “Trust me, it is implemented” is not a demonstration.
