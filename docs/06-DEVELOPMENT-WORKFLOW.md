# Development Workflow
`DEFINE -> PLAN -> APPROVE -> EXECUTE -> VALIDATE -> REVIEW -> ACCEPT/REJECT -> DOCUMENT -> STOP`

A task must be bounded and independently understandable/verifiable. The agent proposes expected changes before implementation. The human approves. Execution stays within scope. Validation runs. Review shows summary, diff, affected files, test evidence, risks and documentation changes. Acceptance records completion; rejection creates bounded correction work.

**Never automatically start the next task.**

Avoid “build the whole application” prompts. Decompose large features while producing an end-to-end visible increment as early as practical.
